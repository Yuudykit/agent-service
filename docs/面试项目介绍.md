# agent-service · 面试项目介绍（一页纸）

> 用途：面试自我介绍里的项目讲解，目标 90 秒讲完主干，留出问答钩子。
> 写作原则：讲系统设计 + 讲取舍 + 主动暴露缺陷（这位面试官吃这一套，"主动坦诚暴露的算好的"）。

---

## 一、一句话定位

一个**手写的、可离线演示的智能体客服**：单文件 500 行级别，实现了 ReAct 循环 + Function Calling + 混合检索 RAG + 三层记忆，配套 58 用例评测（28 基础 + 30 真实多轮）和 19 项单测。真实模式调用 DeepSeek，5 个典型问题 6/6 通过、约 1.9 万 token。

## 二、为什么做这个

不是我拍脑袋选的题，是**对着真实岗位 JD 调研出来的**。我扒了 Agent 开发岗的招聘要求，把高频能力点抽成一张能力图，再反推该做一个什么项目能把它们全覆盖：Function Calling、工具注册、多轮上下文、RAG、评测。项目是**面试能力图的实现投影**，不是练手玩具——这个出发点本身就是「AI 思维」的体现：先调研事实，再动手。

## 三、系统架构（他要的"系统设计"）

分四层，每层职责单一、可替换：

```
┌─────────────────────────────────────────┐
│  入口层   main.py / webapp/ (CLI + Web)  │
├─────────────────────────────────────────┤
│  推理层   core/agent_loop.py             │
│           ReAct 六步循环 + max_steps 护栏 │
│           mock / 真实 双模式（可切换）     │
├─────────────────────────────────────────┤
│  能力层   tools/ (registry 分发)          │
│           search_kb / query_info /        │
│           calculate_refund / transfer…   │
├─────────────────────────────────────────┤
│  知识层   rag/ (embedder/retriever/      │
│           reranker/chunker/build)        │
│           + core/memory.py 三层记忆       │
└─────────────────────────────────────────┘
```

**关键设计决策（讲取舍，不是讲功能）：**

1. **动态分层 system prompt**：角色 / 技能 / 规则 / few-shot 四段。技能段**随工具注册表动态生成**——注册了什么工具才生成对应技能说明。这就是"skill 按需注入"在 miniature 上的实现：上下文里永远只放当前有用的能力描述。**这条直接对应他问的"如何理解 skills / skill 怎么落地"。**

2. **零依赖特征哈希 embedding**：环境没有 numpy/openai 时也能跑离线演示。字符 bigram → crc32 → 512 维向量，TF 加权 + L2 归一化，纯 Python 余弦。面试可现场 `--mock` 跑，不依赖任何 API。**取舍：牺牲精度换可演示性和零部署成本——面试场景下可演示性 > SOTA。**

3. **混合检索**：向量通道 0.6 + 关键词通道 0.4。关键词通道内做口语归一化（"坏了→质量问题"、"退钱→退款"），但**归一化只作用于关键词通道，不污染向量通道**——这是个真实踩坑后的修正：一开始整体替换 query，破坏原始语义，把 kb_026 挤出 top-k。

4. **护栏三件套**：max_steps 防死循环、fallback 防幻觉、边界声明（无关话题明确说"超出服务范围"而不是硬编）。

## 四、技术亮点（问答钩子）

| token 可观测 | `resp.usage` 拦截统计，`--only` 单用例模式 | 成本意识 |

## 五、主动暴露的缺陷（他最吃这套）

我专门写了**一份 11 个 bug 的排查记录**进流程报告，不是藏起来。挑三个讲：

1. **缩进回归**：search_kb 输出从 3 空格改 4 空格，`_mock_chat` 匹配 `"  答："` 失败。**最深的教训**：当时的 28/28 评测全过，但行为是坏的——因为我测的是关键词不是行为。从此我评测改测行为。**这条直接回应他说的"ai coding 工作流代表平时 coding 能力"。**（后续多轮评测扩至 58 用例后，这类回归被彻底关在门外）

2. **哈希稀疏性**：「退钱」vs「退款」余弦只有 0.0467。三层修复（停用词 + 口语归一化表 + kb 补关键词）。**体现"数据准备最难"的真实体感。**

3. **C5 期望词过严**：模型回答正确但没逐字出现"状态"，评测判负。**教训：期望词不能按 mock 输出写死，要贴合真实模型措辞。**

## 六、已知 gap + 下一步（真诚 + 进取心）

1. **单循环架构，没有 subagent**：主 agent 自己干所有事，上下文会随轮数膨胀。下一步 v7：检索类任务派独立 ContextManager 的子循环，回来只交结论——这是我亲手实现一次"上下文隔离"。
2. **skill 体系是静态的**：技能段虽然动态生成，但"技能"本身是写死的。真正的 skill 化（可加载/可路由/可修剪）还没做。
3. **GitHub 已公开**（2026-08-27 上架：API key 已脱敏、冗余已清理、全部文档同步最新）。

## 七、面试 7 问速答卡（他自己列的题，我的答案）

| 题 | 我的答案核心 |
|---|---|
| 选 AI coding 工具 | 按场景分：需环境感知+多步纠错用 agent 型；批处理用脚本+Colab；快验用单轮。判断标准是"任务要不要多步纠错" |
| AI coding 工作流 | 调研先行→小步验证→修复后沉淀（讲义/skill）。实证：11 个 bug 全自己排并记录 |
| 如何用 skill | 重复 3 次以上的工作流固化。实证：我每天学习结束自动生成教学讲义，就是被固化的流程 |
| 如何理解 skills | tool 是"手"（单能力函数），skill 是"肌肉记忆"（领域知识+流程+判断打包）。我的 agent 里 tools/ 是前者，动态 system prompt 是后者雏形 |
| 如何理解 agent | LLM 决策核 + 工具手脚 + 记忆长态 + 护栏（步数/兜底/边界）。难点不在循环，在数据准备和边界控制 |
| 如何理解 harness | 模型外的运行时：上下文管理/工具注册/权限/评测。我在 WorkBuddy 里日用，正逆向 dsh 印证 |
| 如何理解 goal 工程 | 模糊目标拆可验证子目标，每个带判据+止损线。我的 11 天冲刺计划就是 |
