# 电商售后智能客服 Agent · 项目规划书 v1.0

> 日期：2026-08-24 ｜ 定位：面试的展示项目
> 立项阶段归档。当前入口与验证方式见 [README](../../README.md)。
> 原则：每个模块都能在面试现场讲出"我为什么这么写"。

---

## 0. 一句话定位

**一个能现场演示的智能体客服**：用户问问题 → Agent 判断是否调工具 → 检索真实知识库 → 多轮记忆 → 给出有依据的回答；查不到就直说，绝不编造。

---

## 1. 背景与动机

- 面试要求："会写 skill、tool，做智能体客服需要掌握的技能"，还提到 harness
- 真实 JD 要求：RAG、Function Calling、Agent Memory、规划与推理、工具调用、上下文管理、Prompt 工程
- 已具备的零件（前 3 天）：Day 1 手搓 function calling 六步循环（zzz-guide-bot/demo_function_calling.py）、Day 2 手搓 SKILL.md 调度器、Day 3 看懂 dsh 的 harness 概念
- 本次决策：**放弃迁入 dsh，回归手写 Python**——面试考"能不能从零写出来"，不考"会不会用某个框架"

## 2. 目标与成功标准（面试视角）

| 目标 | 成功标准 |

## 4. 技术选型

| 组件 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3.13（managed） | 与 zzz-guide-bot 一致，复用成本最低 |
| LLM | DeepSeek API（deepseek-chat） | 已有 key、便宜、国产可讲 |
| 嵌入模型 | BAAI/bge-small-zh-v1.5（512 维，与哈希向量维度一致） | 中文 C-MTEB 第一梯队、免费离线；备选 BGE-M3（1024 维）/ m3e-small。见 [Embedding 选型报告](../embedding选型报告.md)。 |
| 依赖 | openai / numpy / torch；bge 后端另需 sentence-transformers（可选，见报告第五节） | 核心零框架，本地 embedding 为可选增强 |
| 数据 | **JDDC 京东真实客服数据（v2）** | 10945 会话提炼 47 条 FAQ（见 §5） |

**为什么不用框架**：框架解决工程复用问题，但原理和我写的模块一一对应。

## 5. 数据方案（v2：JDDC 京东真实客服数据）

> v1 曾计划复用 zzz-guide-bot 的游戏知识库；用户明确要求换成真实业务场景数据（游戏只是个人爱好），经调研选定 **JDDC（京东对话挑战赛）真实客服数据**。

**数据来源**：`SimonJYang/JDDC-Baseline-Seq2Seq`（GitHub）→ `data/chat.txt`
- 10,943 个京东真实客服脱敏会话、211,842 条消息、平均 19.4 轮/会话
- 已脱敏（订单号/金额/电话/地址 → `[数字x]` 等标记）
- 主题分布：退款 20.6%、退货 18.1%、售后 17.4%、发货 15.8%、快递 14.3%……

**数据管线**（`scripts/` 三个脚本，全部可复现）：

| 脚本 | 作用 | 产出 |
|------|------|------|
| `data_utils.py` | 共享 JDDC 解析（parse_raw + 基础会话口径），analyze/build_kb/sample 三处复用 | 统一口径，防两处漏改 |
| `analyze_jddc.py` | 解析 chat.txt、统计会话/主题分布 | 控制台报告 |
| `build_kb_from_jddc.py` | 提取"用户问→客服答"候选问答对，按主题归类 | `data/intermediate/faq_candidates.jsonl`（18,341 条，全量 10945 会话） |
| `sample_dialogues.py` | 筛选 8-30 轮、含实质回答的完整会话 | `data/dialogues.jsonl`（120 个会话，带主题/轮数元数据） |
| `enrich_kb.py` | 从 18,341 条候选问答提炼问法变体 | `kb.json` 每条新增 `variants`（40/47 条命中） |
| `build_multiturn_eval.py` | 120 条真实会话 → 多轮评测用例 | `data/eval_multiturn.json`（30 条） |

**最终数据资产**（`data/`）：

| 文件 | 内容 | 用途 |
|------|------|------|
| `kb.json` | **47 条 FAQ 知识库**，11 大主题，每条含 question/answer/keywords/variants，答案从真实客服对话提炼改写 | **RAG 检索源**（variants 增强换说法召回） |
| `dialogues.jsonl` | 120 个真实完整客服会话（含脱敏占位符、主题、轮数） | 生成多轮评测用例的数据源 |
| `eval_set.json` | 28 条基础评测用例（19 工具调用 + 7 边界 + 2 多轮），标注期望行为 | 自动化评测 |
| `eval_multiturn.json` | 30 条真实多轮用例（history + 末轮提问） | 多轮覆盖 2 条 → 32 条（合计 58 用例） |


⚠️ 脱敏标记处理：知识库答案已将 `[数字x]` 等标记改写为自然表达（如"1-3 个工作日"），对话集保留原始标记用于展示真实数据形态。

## 6. 系统架构

```
                        用户输入
                           │
                           ▼
┌──────────────────────────────────────────────┐
│                 main.py（入口/REPL）           │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│        core/agent_loop.py  run()             │
│  ① 加用户消息 → ② 调 LLM → ③ 判断 tool_calls │
│  ④ 执行工具回填 → ⑤ 循环 → ⑥ 输出回答         │
│  （受 reasoning.ReActPlanner 步数约束）        │
└──────┬──────────────┬──────────────┬─────────┘
       ▼              ▼              ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│context.py   │ │prompts.py   │ │registry.py  │
│窗口/截断/摘要│ │分层提示词    │ │注册表+校验   │
└─────────────┘ └─────────────┘ └──────┬──────┘
                                       ▼
                    ┌─────────┬─────────┬─────────┐
                    ▼         ▼         ▼
              search_kb   query_info  fallback
                    │         │         │
                    ▼         ▼         ▼
              rag/retriever  characters.json  转人工话术
                    │
              ┌─────┴──────┐
              ▼            ▼
        rag/embedder  rag/reranker
              │
              ▼
        data/kb.json（JDDC 提炼的 47 条 FAQ）

        横向支撑：core/memory.py（摘要+画像，注入 prompts）
                   eval/eval_script.py（评测）
                   tests/test_agent.py（边界测试）
```

**数据流（一次完整回答）**：
1. `main.py` 收用户输入 → `run(user_input, context)`
2. `context.add_user()` 记录 → `chat()` 调 LLM（带 tools schema）
3. LLM 返回 `tool_calls`（如 `search_kb(query="退款多久能到账")`）
4. `registry.execute_tool()` → 校验参数 → `search_kb` → `retriever.retrieve()` → 返回 top-k 片段
5. 工具结果 `add_tool_result()` 回填 → 再次调 LLM → 模型基于检索内容生成回答
6. 无 tool_calls → 返回最终回答 → 本轮结束，messages 保留到下一轮

## 7. 模块详细设计（按实现优先级 P0/P1/P2）

### P0 —— 核心闭环（先跑通，今天第一优先）

**`core/context.py` — 上下文管理**
- 接口：`add_user / add_assistant / add_tool_result / get_messages / reset`
- 实现要点：
  - `_estimate_tokens()`：中文 1 字≈1 token、英文 4 字符≈1 token、工具结果按字符数打折
  - `_trim_window()`：超 `max_messages`（20）丢最旧 user/assistant，**永远保留最近一轮的完整 tool 回填**（不然模型看不懂工具结果）
  - `_summarize_if_needed()`：超 `summary_trigger_tokens`（3000）时，先截断兜底；真正摘要生成接 memory（P2）
- 验收：20 条消息后窗口不超限；tool 回填不被误删

**`core/agent_loop.py` — Agent 主循环（灵魂）**
- 接口：`chat() / run()`
- 实现要点：
  - `chat()`：mock 模式用关键词匹配（复刻 Day 1 的 `chat_mock` 逻辑）；真实模式用 openai 库调 DeepSeek，`tools=get_tools_schema()`
  - `run()`：循环 `chat → 有tool_calls则逐个execute_tool回填 → 无则返回`，`max_steps` 超限走 fallback
  - 升级 vs Day 1：① messages 归 context 管 ② 工具异常捕获 ③ ReAct 步数约束
- 验收：mock 模式跑通 5 问验收；真实模式（有 key 时）同样跑通

**`tools/registry.py` — 工具注册表**
- 实现要点：`register_tool()`（重复注册报错）、`execute_tool()` 三步——查注册表→参数校验（required/type）→try/except 包裹执行；错误统一返回 `{"ok": False, "error": ...}` 不抛异常
- 错误码约定：`UNKNOWN_TOOL / BAD_PARAMS / INTERNAL / NOT_FOUND`
- 验收：未知工具、坏参数、实现抛异常三种情况都返回结构化错误

**`tools/fallback.py` — 兜底工具（含转人工）**
- 职责：用户问题超出客服范围（天气/闲聊/敏感）时调用，返回"这个我答不了，转人工"话术
- 验收：边界问题走 fallback，不调检索

**`main.py` — 入口 REPL**
- 实现：读 config.json → 建 ContextManager + Memory → 循环 `input()` 收用户输入 → `run()` → 打印回答；支持 `--mock` 参数
- 验收：`python main.py` 能聊天；`python main.py --mock` 无 key 也能跑

### P1 —— RAG 完整化（第二个优先）

**`rag/embedder.py` — 向量化**
- 实现：`EMBEDDER_BACKEND` 切换五类后端（hash 零依赖 / bge-small-zh-v1.5 / bge-m3 / m3e / dashscope API）；本地 ML 后端加载失败降级为哈希向量（保证流程不崩）
- 验收：`encode(["安比"])` 返回对应维度向量（bge 后端 512 维）；加载耗时 3-5 秒可接受

**`rag/retriever.py` — 混合检索**
- 实现：加载 kb.json（复用，含向量）→ `retrieve(query, top_k)`：
  - 关键词通道：query 词在 chunk text 的命中数
  - 向量通道：query 向量 vs chunk 向量余弦相似度（numpy）
  - 加权合并（关键词 0.4 + 向量 0.6，可调）→ top-k
- 验收：`retrieve("安比怎么配队")` 返回含"安比"的真实片段；`use_vector=False` 可对比关键词效果

**`tools/search_kb.py` — 检索工具**
- 实现：补全 schema description（"什么时候调、query 怎么填"）→ `search_kb(query, top_k)` 调 retriever，无匹配返回 `NOT_FOUND`
- 验收：检索命中 → `{"ok": True, "data": {"results": [...]}}`；无命中 → `NOT_FOUND`

**`tools/query_info.py` — 结构化查询工具**
- 实现：读 orders.json → 按订单号精确查订单状态/物流信息
- 验收：`query_info(name="安比")` 返回结构化字段；不存在角色返回 `NOT_FOUND`

**`rag/chunker.py` — 分块（Plan B）**
- 实现：kb.json 够用时只做"按 meta 分组/过滤"的轻量逻辑；需要重建时才做真正分块
- 验收：能对任意长文本按固定长度+重叠切块（函数可用即可，不强制跑）

**`rag/reranker.py` — 重排**
- 实现：轻量重排——对 top-10 结果按"query 关键词覆盖率"重新打分，把精确名词命中排前
- 验收：rerank 后 top-3 比 raw top-3 更相关（对已知测试问题验证）

### P2 —— 增强 + 评测（第三个优先，20:00 前尽力）

**`core/prompts.py` — 分层提示词**
- 实现：5 层结构——角色 / 技能（从 registry 动态生成工具说明）/ 行为规则（不编造、边界兜底）/ few-shot（1 个真实工具调用示例）/ 记忆回顾（memory.recall() 动态注入）
- 验收：system prompt 能体现"查不到就直说"；few-shot 示例格式与真实调用一致

**`core/memory.py` — 对话记忆**
- 实现：`update_profile()` 规则抽取（正则："我主玩X" "我喜欢X" → profile KV）；`recall()` 生成注入文本；`_load/_save` JSON 落盘
- 降级：LLM 摘要（`summarize()`）若时间不够，先用规则摘要（取每轮关键句），接口保留
- 验收：说"我主玩安比"→ 下一轮回答里体现记忆；重启进程后记忆还在（data/memory.json）

**`core/reasoning.py` — ReAct 规划**
- 实现：`should_continue()`（步数上限/异常终止）、`extract_action()`（解析 `Action: search_kb({...})`）、`extract_final_answer()`
- 集成：agent_loop 的 `max_steps` 用它约束；可先做"步数控制"版，Action 解析 P2 尾部
- 验收：3 步上限内终止；超限转 fallback

**`eval/eval_script.py` — 评测**
- 实现：预置 5 个问题（配队/属性/边界/防幻觉/多轮）→ 跑 `run()` → 记录三指标：工具调用正确率 / 回答含关键事实率 / 兜底正确率 → 打印报告
- 验收：mock 模式下跑出报告，指标可解释

**`tests/test_agent.py` — 边界测试**
- 实现：pytest 风格（无 pytest 依赖时用 assert + 主函数）——5 个测试：工具调用、多轮记忆、边界守卫、防幻觉、上下文窗口
- 验收：`python tests/test_agent.py` 全绿
